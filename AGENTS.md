# AGENTS.md — Voica site

Область работы — сайт Inhum/voica-site. Приложения macOS и Windows
развиваются в отдельных репозиториях.

## Порядок работы

- Общайся по-русски, прямо и по делу: сначала вывод, затем факты.
- В начале работы подтверди фактический корень репозитория, origin
  (скрыв встроенные credentials), ветку, HEAD, staged, unstaged и untracked.
  Сохраняй пользовательские изменения: не отменяй и не включай их
  в свою работу автоматически.
- До изменений согласуй конкретный объём. Одобренное выполняй
  без повторных вопросов.
- Предпочтительный процесс: задача → ветка → проверки → PR →
  согласованное слияние. Учитывай автоматическую сборку и публикацию;
  изменение самого процесса требует согласования.
- Коммит, push, создание PR, merge и публикация требуют явного
  согласования. Одно конкретное поручение может разрешать несколько
  этих действий вместе; не запрашивай разрешение повторно
  в уже согласованном объёме.
- Не создавай дополнительные клоны или worktree и не клонируй соседние
  репозитории без отдельного согласования. Fetch, pull и переключение
  ветки должны входить в согласованный объём.
- Найденное вне задачи сообщай отдельно; не исправляй автоматически
  и не возобновляй старые планы.
- Не создавай PROGRESS.md, копии памяти, новые зависимости, настройки
  среды или автоматизации без отдельного согласования.
- Не читай и не публикуй секреты и частные материалы. Не отправляй
  сообщения в другие чаты без явного поручения.
- В сообщения будущих коммитов, подготовленных с помощью OpenAI Codex,
  добавляй трейлер `Co-authored-by: Codex <noreply@openai.com>`.
  Не выдумывай имена и e-mail авторов или соавторов.

## Источники и устройство сайта

Перед работой прочитай применимые AGENTS.md, README.md и относящуюся
к задаче документацию; перед изменением оформления — BRAND.md.

- Сайт статический: RU — index.html, EN — en/index.html.
- src/build.py — исходник текстов RU/EN, метаданных, шаблона и встроенного
  JavaScript. Обе HTML-страницы генерируются; вручную их не правь.
- BRAND.md задаёт правила бренда, assets/css/tokens.css — дизайн-токены,
  assets/css/site.css — стили компонентов. Шрифты хранятся локально.
- llms.txt, robots.txt, sitemap.xml, CNAME и изображения поддерживаются
  отдельно. При изменении публичных утверждений проверяй связанные
  метаданные, структурированные данные и сопутствующие материалы.
- README.md и .github/workflows/ описывают сборку и публикацию.
  Подробные технические сведения храни в обычной документации;
  не копируй целые skills в AGENTS.md.

## Утверждения о приложениях

Канон требований к поведению:
https://github.com/Inhum/voica/blob/main/docs/CORE-SPEC.md

Различай требования, main/Unreleased, фактическую реализацию, результаты
проверок и опубликованные стабильные Releases. Матрица паритета, код main
или наличие требования не доказывают доступность функции пользователю.

Проверяй стабильные выпуски и опубликованные артефакты отдельно:
- macOS: https://github.com/Inhum/voica/releases
- Windows: https://github.com/Inhum/voica-win/releases

Учитывай платформенные различия и ограничения движков. Не представляй
возможности кандидатов в релиз как доступные в стабильной версии.
Сохраняй смысловой паритет RU/EN и точность утверждений о приватности.
Не фиксируй текущие версии приложений в этой инструкции.

## Проверки и публикация

Выбирай проверки по согласованной задаче. При аудите только чтением
не изменяй checkout. Чужие отчёты отделяй от собственных проверок;
невыполненные проверки и ограничения указывай явно.

Генерация из корня: python3 src/build.py.
Она перезаписывает обе HTML-страницы; запускай её только в согласованном
объёме, допускающем запись.

Для изменений сайта проверяй обе локали, относительные пути, ссылки
скачивания, метаданные и соответствие BRAND.md. Для визуальных изменений
проверяй обе темы, мобильный вид, видимый фокус и reduced-motion.
Для правок только документации достаточно проверки текста и diff.

По README сайт публикуется через GitHub Pages из корня ветки main.
Workflow Build site может сам коммитить и отправлять сгенерированные
страницы. Перед действиями, способными вызвать публикацию, проверь
актуальные workflow, настройки Pages и публикуемую ревизию.
Успех Actions не заменяет проверку опубликованного сайта.
